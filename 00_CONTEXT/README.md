# Context System README

This folder is the persistent memory layer for future agents. It is designed to work for any model: GPT, Claude, Gemini, or another coding agent.

## What To Read First

1. `AGENTS.md` - mandatory operating manual.
2. `00_CONTEXT/REPO_MAP.md` - repository map and domain boundaries.
3. Folder `CONTEXT.md` - local writing style and risks.
4. `00_CONTEXT/FILE_REGISTRY.md` - generated inventory of active Markdown files.
5. `00_CONTEXT/DECISIONS.md` - permanent repo decisions.
6. `00_CONTEXT/CONTAMINATION_GUARDS.md` - known wrong-domain copy patterns to avoid.
7. `00_CONTEXT/CHANGE_JOURNAL.md` - recent context-changing work.

## Core Idea

Do not rely on a single chat transcript to remember the repo. The repo carries its own context:

- Human context: maps, decisions, folder notes, update protocol.
- Machine context: generated file registry and hash manifest.
- Freshness checks: a script detects files changed since the last registry update.

## Commands

Check whether context is fresh:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/update_context.ps1 -Mode check
```

Fail the check on Markdown fence warnings too:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/update_context.ps1 -Mode check -StrictFences
```

Regenerate the file registry and manifest:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/update_context.ps1 -Mode update
```

## Generated Files

`FILE_REGISTRY.md` and `CONTEXT_MANIFEST.json` are generated by `tools/update_context.ps1`.

Do not hand-edit the generated table unless the script is broken. If the registry is stale, regenerate it after updating the human context files.
