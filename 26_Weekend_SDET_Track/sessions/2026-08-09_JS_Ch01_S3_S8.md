## §3 — Type Coercion

### The whole section, compressed to one rule

> Math operators (`-`, `*`, `/`, `%`) always convert to **number**.
> `+` is **overloaded** — it does addition *and* concatenation — so if **either** side is a string, `+` picks concatenation and converts the other side to a string.

Everything else in the section follows from that:

```js
"5" + 3      // "53"   — + saw a string, chose concatenation
"5" - 3      //  2     — minus has no string mode, converted to number
"5" * "2"    // 10     — both converted to number
"hello" - 3  // NaN    — Number("hello") has no sensible answer
```

*All verified by execution.*

### `ToPrimitive` — the part worth remembering by name

When an object needs to become a primitive, the engine tries **`valueOf()` first**, then falls back to **`toString()`**. Arrays and plain objects don't override `valueOf`, so it hands back the object itself — not a primitive — and `toString()` wins:

```
[].valueOf()    → []                  not a primitive → keep going
[].toString()   → ""                  primitive → use this
({}).toString() → "[object Object]"

[] + {}  →  "" + "[object Object]"  →  "[object Object]"    ✅ verified
```

That `"[object Object]"` string is the one you'll actually meet in the wild — usually when someone interpolates an object into a template literal or a test name.

### 🎯 The SDET consequence — this is the part that matters for you

Playwright's `textContent()`, `inputValue()`, and `getAttribute()` all return **strings**. So:

```js
const count = await page.textContent('.cart-count');  // "3" — a string, always

expect(count == 3).toBe(true);    // ✅ passes — silently coerced
expect(count === 3).toBe(true);   // ❌ fails — types differ
```

**The first one passing is worse than it failing.** It also passes when the element renders `"3 "` with trailing whitespace, or `"03"`, or `"+3"`. Coercion hides the exact bug the test was written to catch.

**Rule:** use `===`, and convert explicitly with `Number(count)` when you mean a number. Let the conversion be a thing you wrote, not a thing the engine did behind you.

### Falsy values

Eight, at the language level: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`.

Everything else is truthy — **including `"0"`, `"false"`, `[]`, and `{}`**. Verified. The empty-array-is-truthy one catches people constantly: `if (results)` is `true` even when `results` is empty. You want `if (results.length)`.

> ⚠️ In a **browser** there's a 9th: `document.all`. See [audit log A3](../03_Content_Audit_Log.md).

### `==` vs `===`

Default to `===`. The one sanctioned exception is `value == null`, which catches **both** `null` and `undefined` in a single check — verified against 11 probe values (`0`, `-0`, `""`, `"0"`, `false`, `NaN`, `[]`, `{}`, `0n`, `Infinity`, `" "`), none of which loosely-equal `null`. That narrowness is what makes it safe.

## §8 — Execution Context

### What it is

A record the engine creates **every time it's about to run code** — once for the top-level script, and fresh on every single function call. It holds exactly three things:

1. **Variable Environment** — bindings declared in this invocation
2. **Scope Chain** — a link outward to the parent, so lookups can walk up
3. **`this` binding** — decided by the **call site**, not where the function was written

### The insight worth extracting

A fresh context per call, each with its own independent variable environment, is **why recursion works at all**. Each recursive call needs its own copy of the locals — per-call contexts are precisely how that independence is provided. Same mechanism, different angle, is why closures can capture distinct values.

### The call stack

Where active contexts live. Pushed on call, popped on return, strictly LIFO.

```
┌───────────────┐
│ inner()       │ ← currently executing
│ outer()       │ ← waiting for inner() to finish
│ Global        │ ← waiting for outer() to finish
└───────────────┘
```

**A stack trace is a snapshot of this stack, read top-down.** Learning to read one properly is a daily SDET skill — and it's this exact structure underneath.

Overflow it and you get `RangeError: Maximum call stack size exceeded` — verified, at **12,550 frames** on this machine (the chapter says ~10,000; see [audit log A1](../03_Content_Audit_Log.md) — the number varies, don't depend on it).

### Node vs browser `this` — verified

```
this === module.exports  →  true
```

Top-level `this` in Node is `module.exports`, **not** `globalThis`. The mechanism, pulled live from `require('module').wrapper`:

```js
(function (exports, require, module, __filename, __dirname) {
```

Node never runs your file at global scope — it wraps the whole file in that function and calls it with `this` set to `module.exports`. So it isn't Node magic; it's the ordinary implicit-binding rule applied to a call Node makes on your behalf. In a browser there's no wrapper, so top-level `this` is `window`.
