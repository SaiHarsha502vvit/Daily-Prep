## FOLDER-LEVEL OBSERVATIONS

### Strongest Dimension: Topical Breadth (TB)

Most files enumerate 2+ variants and include comparison tables or decision matrices. The decision-tree / comparison-table pattern is well-established across the folder (e.g., sorting algorithms table in 02a/02b, DP pattern table in 04b, Greedy vs DP vs Backtracking in 12_Greedy, BFS/DFS/Dijkstra decision table in 05c).

### Weakest Dimension: Historical Evolution (HE)

Only 8 files reference historical years, and most of those are concentrated in `12_Algorithms_In_Production.md` (full timeline) and `12_Greedy_Algorithms_Complete.md` (Huffman 1952, Kruskal 1956, Prim 1957, Dijkstra 1959). Most algorithm files lack:

- Named inventors/years (Dijkstra 1959, Floyd-Warshall 1962, Bellman 1957, Huffman 1952, Kruskal 1956, Prim 1957, Hoare 1959 not referenced)
- Predecessor named
- Evolution/motivation paragraph
- Modern practice anchored post-2010

### Consistent PC (Pedagogical Craft) Issues

- **Duplicate answer blocks**: Sections `02a_Sorting_Fundamentals.md`, `02c_Divide_And_Conquer.md`, `12_Greedy_Algorithms_Complete.md`, and several others include a `🔬 **Section Challenge**` block whose `<details><summary>Answer</summary>` block is followed by a second orphaned `<details>` block containing a previously-seen answer (the two-pointer invariant answer appears at least 5 times across different files). This is cross-file contamination from boilerplate reuse.
- **Duplicate challenge blocks**: Files that share the same top-level challenge (e.g., binary search trace, fibonacci O(2^N) bug hunt) across `01_Algorithm_Thinking.md`, `02c_Divide_And_Conquer.md`, `03a_Recursion_Internals.md`, `06a_Greedy_BitManip.md`, `20_DSA_Patterns_PDF_Java_Coverage_Map.md`. These appear to be copy-pasted from a shared template rather than locally authored.
- **Missing 5W1H**: `06d_String_Algorithms.md`, `06e_Algorithm_Patterns.md` use `<details>`-wrapped 5W1H blocks instead of the canonical 5W1H box format. `09_Pattern_Programs_Complete.md` and `10_Bit_Manipulation_Complete.md` lack 5W1H entirely.

### Consistent CD (Conceptual Depth) Issues

- Most files have the mental model paragraph (the opening `WHY` block) but lack an explicit `invariant` statement with the word "invariant" followed by a noun phrase.
- Only files that explicitly state "The invariant is...": `01_Algorithm_Thinking.md` (two-pointer invariant), `04c_DP_Advanced.md` (bitmask invariant), `05d_Graphs_Advanced_Algos.md` (Dijkstra invariant), `14_Union_Find_DSU_Complete.md` (disjoint-set invariant), `18_Bitwise_Trie_Java_Complete.md` (2^k domination principle), `15_Monotonic_Stack_Queue_Complete.md` (push/pop amortized invariant).
